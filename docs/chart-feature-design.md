# ออกแบบคำสั่งกราฟ — ผู้ช่วยเอไอธานีพิทักษ์

สถานะ: เพิ่มคู่มือกราฟตามสังกัด ปุ่ม/เลขลำดับ และคำสั่งตัวอย่างทั้งสี่ลงแอปแล้ว รายละเอียดโดนัท แท่งซ้อน ส่งออกกราฟ และแผงผลวิเคราะห์ด้านล่างยังเป็นข้อเสนอ

วันที่: 2026-09-28 • อ้างอิง branch `phase-3.3-low-latency`, commit `0f5a0a1`

## ประสบการณ์ที่ต้องการ

ผู้ใช้พิมพ์หรือพูดคำสั่งในช่องสนทนาเดิม ระบบตอบข้อความสรุปพร้อมกราฟในผลลัพธ์เดียวกัน สามารถเปลี่ยนชนิดกราฟหรือเปิดตารางตัวเลขจากข้อมูลชุดเดิมได้ ทุกกราฟระบุพื้นที่ ประเภทข้อมูล ช่วงเวลา/เวลาที่อ่าน หน่วย แหล่งข้อมูล และข้อจำกัดที่เกี่ยวข้อง

แนะนำเริ่มจาก **กราฟในบทสนทนา** เพราะเข้ากับขั้นตอนใช้งานเดิม ทั้งโหมดพิมพ์และโหมดเสียง ส่วน **แผงผลวิเคราะห์** เป็นตัวเลือกการจัดหน้าสำหรับการขยายภายหลัง

คำศัพท์ที่ต้องรองรับ: กราฟ, แผนภูมิ, ชาร์ต, chart, graph; แท่ง/แท่งแนวนอน, เส้น, แท่งซ้อน, วงกลม/โดนัท รวมถึงอนุภาคสุภาพและตัวเลขไทยหลังผ่าน normalization เดิม

กราฟเส้นต้องมีข้อมูลเวลาจริง หากผลล่าสุดเป็นจำนวนบุคคลแยกประเภท ให้เสนอกราฟแท่งหรือโดนัท ไม่สร้างแกนเวลาขึ้นเอง เมื่อคำสั่งมีหลายความหมาย ให้ถามเฉพาะสิ่งที่ขาด เช่น “ต้องการจำนวนบุคคล หรือจำนวนครั้งที่ตรวจเยี่ยม?”

## ข้อมูลและกติกาของกราฟ

- หน่วย `คน` ใช้กับผลรวมทะเบียนบุคคล; หน่วย `ครั้ง` ใช้กับบันทึกตรวจเยี่ยม ไม่ใช้แทนกัน
- `overview.byType`, `target_person_summary.rows/totals`, `station_ranking.rows`, `location_summary.items`, และ `visit_summary.months/byType` เป็นรูปข้อมูลต้นทางที่สามารถเพิ่ม adapter ได้
- รายชื่อบุคคลที่แบ่งหน้าไม่ใช่ผลรวมครบทั้งขอบเขต จึงห้ามนับแค่หน้าที่เห็นเพื่อสร้างกราฟภาพรวม ต้องเรียก aggregate ที่ได้รับอนุญาต หรือปฏิเสธว่าข้อมูลไม่ครบ
- กราฟเส้นรายเดือนแสดงเฉพาะค่าที่บันทึกแล้ว ไม่พยากรณ์ เดือนที่ยังไม่จบต้องระบุวันสิ้นสุดจริง เช่น “กันยายนถึงวันที่ 28”
- เดือนที่แหล่งข้อมูลยืนยันว่าไม่มีรายการแสดงเป็นศูนย์ได้ แต่เดือนที่อ่านไม่ได้/อ่านไม่ครบเป็นข้อมูลไม่พร้อม ห้ามแทนด้วยศูนย์
- โดนัทใช้เฉพาะประเภทที่ไม่ซ้ำกันและรวมเป็นยอดเดียวกัน ผลรวมทุกส่วนต้องตรงกับยอดรวม; เก็บ “อื่น ๆ/ไม่ระบุ” หากมีจริง ไม่ลบทิ้งเพื่อให้กราฟสวย
- แท่งเริ่มแกนค่าที่ศูนย์; ชื่อสถานีหรือพื้นที่ยาวใช้แท่งแนวนอน; ป้ายหน่วยและตัวเลขต้องอ่านได้บนมือถือ
- หากใช้ Top N ต้องระบุ “N อันดับแรก” และขอบเขตชัดเจน ไม่เรียกผลส่วนนี้ว่าทั้งจังหวัด การรวม “อื่น ๆ” ทำได้เมื่อมีผลรวมครบเท่านั้น
- การสรุปหลายประเภทต้องรวมจากชุดประเภทที่เลือกจริง ต้องตรวจ `visit_summary.total`, `totalAll`, `months.total` และ `months.byType` ให้สอดคล้องกันก่อนสร้างกราฟ ไม่ถือว่ายอดรวมรายเดือนเป็นยอดของประเภทที่เลือกโดยอัตโนมัติ
- กราฟระดับเฝ้าระวังใช้ระดับจากบันทึกจริงตามกติกาเดิม ไม่เพิ่มสูตรหรือ threshold จาก fixtures

## การต่อเข้าระบบเดิม

ยังใช้ `/api/ai/chat` และขั้นตอน STT เดิม เพิ่มการตรวจคำสั่งกราฟแบบ deterministic ก่อน fallback ไปโมเดล โดยแยก “รูปแบบแสดงผล” ออกจาก “เงื่อนไขข้อมูล” และรักษาประเภท พื้นที่ ช่วงเวลา และข้อยกเว้นทั้งหมด

โมดูลที่เสนอ:

1. `src/ai/chartIntent.js`: ตรวจคำสั่งตรง/คำสั่งต่อเนื่อง เลือกเฉพาะ enum ที่อนุญาต ไม่สร้าง SQL หรือโค้ดจากข้อความผู้ใช้
2. `src/services/chartPresentation.js`: แปลงผลรวมที่ตรวจสิทธิ์แล้วเป็นข้อมูลกราฟ พร้อมตรวจหน่วย ความครบถ้วน ยอดรวม และขอบเขต
3. `frontend/charts.js`: วาดกราฟ รับเฉพาะข้อมูลและชนิดกราฟที่กำหนดไว้ ไม่มีการ execute HTML/JavaScript จากโมเดล
4. เพิ่ม branch ใน `realDataRoutes.js` และ test-mode gateway โดยใช้ data tool เดิม พร้อมเชื่อม renderer ใน `frontend/ai.js`

รักษา `presentation.type` เดิมเพื่อไม่กระทบตาราง/การเลือก/รายงาน เพิ่ม `presentation.chart` เป็นส่วนเสริม ตัวอย่าง **รูปข้อมูลที่เสนอ**:

```json
{
  "type": "visit_summary",
  "chart": {
    "version": 1,
    "kind": "stacked_bar",
    "title": "การตรวจเยี่ยมรายเดือน",
    "unit": "ครั้ง",
    "labels": ["เมษายน 2569", "พฤษภาคม 2569"],
    "series": [
      { "key": "psychiatric", "label": "จิตเวช", "values": [0, 0] },
      { "key": "drug_user", "label": "ผู้เสพ", "values": [0, 0] }
    ],
    "scopeLabel": "พื้นที่จากผลรวมที่ตรวจสิทธิ์แล้ว",
    "from": "2026-04-01",
    "to": "2026-05-31",
    "asOf": "เวลาที่อ่านข้อมูล",
    "source": "recorded_visits",
    "complete": true,
    "notes": []
  }
}
```

ตัวเลขใน schema นี้เป็น placeholder ไม่ใช่ข้อมูลทะเบียน กราฟต้องใช้ตัวเลขที่ได้จากการอ่านจริงที่ได้รับอนุญาตเท่านั้น

ชนิดที่อนุญาตรุ่นแรก: `bar`, `line`, `stacked_bar`, `donut` เท่านั้น Renderer รับ label เป็นข้อความ และปฏิเสธข้อมูลผิดชนิด ค่าติดลบ/ไม่เป็นจำนวน และความยาว series ที่ไม่ตรงกับ labels

คำสั่งเปลี่ยนรูปกราฟใช้ snapshot ของผลรวมที่อ่านสำเร็จแล้วในหน่วยความจำของหน้าเว็บ ไม่ส่ง series จาก browser กลับไปให้ server เชื่อว่าเป็นข้อเท็จจริง หากต้องเปลี่ยนพื้นที่/ช่วงเวลา ต้องอ่านใหม่และตรวจสิทธิ์ใหม่ กราฟเดิมระบุ `asOf` ไม่แสดงว่าเป็นข้อมูลสด

ให้มี snapshot อ้างอิงเพียงผลข้อมูลล่าสุด เมื่อผลใหม่ไม่สามารถทำกราฟได้ ให้ระบุหรือขอเลือกข้อมูลให้ชัด ไม่ย้อนใช้กราฟเก่าอย่างเงียบ ๆ ล้าง snapshot เมื่อ logout เปลี่ยน source หรือเริ่มบทสนทนาใหม่ และป้องกันผลคำขอเก่าปรากฏหลังเปลี่ยน source

## สิทธิ์และ audit

- ข้อมูลจริงใช้ authenticated Supabase user token และ scope ที่ server ตรวจสอบจากระบบหลักเท่านั้น เงื่อนไขพื้นที่ในคำสั่งเป็นตัวกรอง ไม่ใช่การให้สิทธิ์เพิ่ม
- ทุกการอ่านข้อมูลจริงใหม่ต้องมี audit ที่ระบุ actor, timestamp, request type, พื้นที่ที่ขอ และ result metadata การเปลี่ยนชนิดกราฟจาก snapshot ไม่อ่านทะเบียนเพิ่ม
- ต้องตรวจว่า adapter ต้นทางมี audit ครบจริง เส้นทาง REST โดยตรงในแอปไม่ควรถูกถือว่า audited เพียงเพราะใช้ user token หรือมี RLS หากยังยืนยันไม่ได้ ต้องต่อผ่าน audited allowlisted RPC/Edge tool หรือเพิ่มกลไก audit ที่ระบบหลักก่อนเปิดใช้กราฟนั้น
- กราฟรุ่นแรกใช้ข้อมูลรวม ไม่ส่งเลขบัตร โทรศัพท์ PIN JWT หรือข้อมูลรายบุคคลเข้า model/กราฟ/ไฟล์ส่งออก ไม่เพิ่มสิทธิ์เขียนทะเบียน
- ข้อมูลทดสอบแสดงป้ายแหล่งข้อมูลชัดเจน ฟีเจอร์ที่ต้องมีบันทึกจริง เช่น สถิติตรวจเยี่ยม ต้องปฏิเสธใน test mode ตามพฤติกรรมเดิม ไม่ใช้ fixtures มาทดแทน
- หากไม่รองรับช่วงเวลา/ข้อยกเว้น/แหล่งข้อมูล ให้ตอบข้อจำกัดอย่างชัดเจนและเสนอคำสั่งที่รองรับ ไม่ทิ้งเงื่อนไขแล้วแสดงข้อมูลกว้างขึ้น

## ลำดับพัฒนาและเกณฑ์ผ่าน

รุ่นแรก: คำสั่งตรง + เปลี่ยนกราฟของผลล่าสุด + กราฟ/ตาราง + แท่ง/โดนัทสำหรับทะเบียน + เส้น/แท่งซ้อนสำหรับสถิติตรวจเยี่ยม หลังผ่านการตรวจ audit ของต้นทางแต่ละชนิด

ขั้นถัดไป: ดาวน์โหลด PNG และ PDF ที่ฝังกราฟ โดยรักษาพื้นที่ ช่วงเวลา หน่วย `asOf` และหมายเหตุเดียวกัน ยังไม่ถือว่ารายงาน PDF เดิมฝังกราฟได้แล้ว

Regression ที่ต้องมีเมื่อพัฒนา:

- ภาษาพิมพ์/เสียง ไทย/อังกฤษ/ตัวเลขไทย และคำสุภาพ
- คำสั่งต่อเนื่อง ไม่มีผลอ้างอิง ผลล่าสุดเป็นรายชื่อแบ่งหน้า หรือเปลี่ยน source ระหว่างรอ
- ประเภท/พื้นที่/ช่วงเวลา/ข้อยกเว้นไม่หลุดเมื่อเติมหรือเปลี่ยนชนิดกราฟ
- Scope ระดับสถานีและข้ามสถานีที่ server อนุญาต; body/model ปลอม scope เพิ่มสิทธิ์ไม่ได้
- ทุก real read มี audit metadata ครบ; ทดสอบโดย mocked server เท่านั้น
- โมเดลล้มเหลวต้องไม่กระทบคำสั่งที่ deterministic และไม่สร้างตัวเลขจาก prose
- รวมหลายประเภท/ศูนย์ข้อมูล/อ่านไม่ครบ/เดือนบางส่วน/ยอดรวมไม่ตรง
- ตารางกับกราฟใช้ตัวเลขชุดเดียวกัน และอ่านได้บน PC/mobile/โหมดเสียง
- รัน `npm test` สำหรับการแก้ routing/auth/data พร้อมแยกรายงานผล fixture/mock, actual Ollama และ authenticated real data

ต้นแบบหน้าตาใช้ข้อมูลสมมติเท่านั้น ไม่ได้เรียกทะเบียนหรือโมเดลจริง และไม่ใช่หลักฐานว่าคำสั่งกราฟทำงานในแอปแล้ว
