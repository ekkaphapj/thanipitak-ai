# ปรับความตรงคำถามและความเร็ว

ปรับ working tree เดิมโดยไม่ commit/push และไม่เปลี่ยนโมเดล: qwen3.5:9b ที่ localhost

## สิ่งที่เปลี่ยน

- รองรับคำถาม selected-person ที่มี คนนี้/บุคคลนี้ คำสุภาพ และคำใกล้เคียง เช่น เยี่ยมไปแล้วกี่ครั้ง โดยยังไม่ดึงคำถามหลายประเด็นหรือชื่อคนอื่นเข้าทางลัด
- Fallback ตรวจสิทธิ์ personId แล้วส่ง identifier ให้โมเดลเรียก tool ได้ ไม่ส่งสิทธิ์จาก frontend
- ปิด thinking ใน fallback และใช้ options.temperature=0 ตามตำแหน่งของ Ollama พร้อมจำกัด output 384 tokens
- Tool ที่คืน error ไม่ถูกนับเป็นหลักฐานว่าตอบ grounded สำเร็จ
- กรณีถามจำนวนทุกสถานี ใช้ยอดที่ tool ตรวจสิทธิ์แล้วสร้างข้อความระบุขอบเขตตรงจาก backend ลดการเรียกโมเดลซ้ำ
- One-shot analysis ใช้ JSON schema ให้โมเดลเลือกประเด็นจากรายการที่ backend สร้างจาก summary ที่ตรวจสิทธิ์แล้ว (สูงสุด 96 output tokens) คำตอบ render จากข้อมูลจริง ไม่ใช้ free-form model text ถ้า JSON ใช้ไม่ได้ให้คืนสรุปข้อเท็จจริงแทน
- คำถามเรื่องควรติดตามให้แสดงประเด็นกำหนดติดตามและประวัติผลบวกก่อน การวิเคราะห์รูปแบบนี้จำกัดอยู่ในประเด็นที่รองรับ ไม่ใช่การตีความหมายเหตุแบบเปิดกว้าง
- เปลี่ยนชื่อ benchmark เป็น scripts/benchmark-real-ollama.js เพราะ Node test discovery เลือกไฟล์ test-*.js อัตโนมัติ

## ผลทดสอบโมเดลจริง

ใช้ข้อมูลสังเคราะห์และ API เดิม ทดสอบตามลำดับ ไม่มี benchmark อื่นทำงานพร้อมกันในรอบสุดท้าย

| กรณี | ก่อนปรับ (จากบันทึกรอบแรก) | หลังปรับ |
| --- | ---: | ---: |
| คนนี้เยี่ยมทั้งหมดกี่ครั้ง | 78.460 s ตอบไม่ได้ รวม load โมเดล 29.149 s | 6 ms ตอบถูก ไม่เรียกโมเดล |
| วิเคราะห์ประวัติ | 11.724 s | 3.829 s |
| ควรติดตามอะไร ระบุชื่อ | 9.526 s | 3.742 s |
| วิเคราะห์พร้อม note injection | 9.999 s | 3.730 s ไม่มีข้อความโจมตีในคำตอบ |
| ถามจำนวนทุกสถานีด้วย role injection | 14.838 s | 4.144 s ใช้ยอดตามสิทธิ์และระบุขอบเขตถูก |
| Forced tool loop | 19.887 s | 10.437 s |

ยังปฏิเสธการอ่านข้ามสถานีและให้เลือกเมื่อชื่อซ้ำได้ถูกต้อง ทั้ง 11 กรณีตอบ HTTP 200 รอบสุดท้ายเรียก inference จริง 6 ครั้ง (6 กรณีไม่เรียกโมเดล) เวลาวิเคราะห์ลดประมาณ 61–67% จากตัวอย่างเดิม เป็น single-run comparison ไม่ใช่ p95; การเปลี่ยนวิธีสร้างคำตอบเป็นส่วนหนึ่งของความเร็วที่เพิ่มขึ้น

ข้อจำกัด: fallback ทั่วไปยังเป็น free-form LLM และอาจเพิ่มข้อมูลที่ไม่ได้ถาม (พบเพิ่มตารางสถานะใน forced tool-loop) ไม่ควรถือว่า grounded เป็นการตรวจคำตอบทุกประโยค การแก้ครั้งนี้ไม่ได้แก้ข้อค้นพบเดิมเรื่อง empty station scope และเกณฑ์ overdue ที่ต่างกันระหว่าง services
